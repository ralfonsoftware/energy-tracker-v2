- (capability) CAP-1 Meter Reading Entry & Habit Loop — intent: log a Main Meter kWh+timestamp reading in under a minute from a phone, backfillable, offline-safe. success: sub-minute default save; distinct-timestamp same-day readings both accepted; offline entries queue and sync without duplicate or loss (idempotency key). Sources: FR-1, AD-16.
- (capability) CAP-2 Pattern Detective: Gap-Tolerant Baseline & Status — intent: compute a single glanceable Status (within range/below baseline/trending) from a gap-tolerant rolling baseline over irregular readings vs. a household Yearly Baseline, flagging long gaps and meter regressions before they corrupt pace. success: multi-day gaps never break/reset the baseline; Status recomputes only on new reading/completed import, never a fixed schedule; a lower-than-previous reading opens a reset/rollover prompt and is excluded from pace math until resolved; historical Status is never rewritten by a later settings edit. Sources: FR-2,3,6,7,8,25; AD-4,7,11,12,14.
- (capability) CAP-3 Smart Plug Import & Baseline Sharpening — intent: upload Eve Home/Meross export files to sharpen the baseline and browse measured per-Room/PowerPoint/Device context, never required or reconciled against the Main Meter total. success: zero-Smart-Plug households still get a fully functional Status; import is fully async with completion notification; in-range gaps are capped/flagged not zeroed; retagging after import leaves prior data on its at-import tag. Sources: FR-4,5,9,24; AD-9,10,14.
- (capability) CAP-4 Tariff Savings Radar — intent: compare current Tariff vs. a candidate rate with switching bonuses normalized out, and get a reminder to re-check only once a contract-exit window opens. success: bonus-included and bonus-normalized signals always shown together, never toggled; exact breakeven resolves to not-worth-switching; reminder never fires >3 months before contract-period end or with no Tariff configured. Sources: FR-10-15; AD-5.
- (capability) CAP-5 Context Capture & Wattage Plausibility — intent: log a short text/tap event for an appliance no Smart Plug sees, and get a rough never-false-precision correlation against the deviation Pattern Detective observed, via a household-configured AI backend (local/cloud/off). success: logging effort matches Meter Reading entry; an event with no observable deviation shows without a correlation rather than a wrong flag; disabling AI leaves the rest fully functional. Sources: FR-16,17,18; AD-8.
- (capability) CAP-6 Extensible Platform — intent: extend behavior (custom event/plausibility rules, new Smart Plug formats, tunable thresholds) without a core code change. success: threshold/spike settings adjustable via UI not config-file edits; the event-rule seam is ready for voice input to plug in later as a new input modality. Sources: FR-19-21.
- (capability) CAP-7 Data Export/Import — intent: export the full Household dataset for disaster-recovery backup and import it to restore or migrate a v2 instance. success: import validates against the documented v2 format and rejects/reports malformed data rather than partially applying it; importing into a Household with existing data is blocked pending an explicit replace-all confirmation. Sources: FR-22,23; AD-2,3.
- (capability) CAP-8 Household & Access — intent: first visitor to a fresh deployment creates a Household and can invite members, all authenticated via a config-swappable OIDC provider with equal access and durable phone sessions. success: fresh deployment routes any authenticated visitor into Household creation, never a broken/empty dashboard; all members equal access (no admin role); session survives app restarts and cold starts. Sources: FR-26-28; AD-3,15,17.
- (constraint) Main Meter reading is the sole source of truth for total consumption; no code/API/view may sum or reconcile Smart Plug or Event data against it — no Residual type anywhere (AD-14). Rules out any drill-down chart or endpoint that shows a summed-measured-total series alongside meter-derived pace.
- (constraint) Every swappable capability (DB provider, OIDC, AI backend, job queue) is one config value, never a code fork; one container image serves both self-host and Azure (AD-1,2,6,8,13). Rules out provider-specific code paths and a split frontend/backend deployment.
- (constraint) No third-party account or phone-home telemetry required; self-hosted by default, data always exportable, no paid third-party service required for a basic instance; optional AI integration degrades gracefully, never a hard dependency.
- (constraint) Every route requires authentication except the OIDC callback; all data isolated per Household at the data-access layer, not by convention in each handler (AD-3).
- (constraint) Monetary values are fixed-decimal (never float); timestamps are ISO 8601 with explicit offset; no hardcoded locale/currency/household-specific value anywhere — presets are suggestions, never silently-applied defaults; new Locales are a resource-file addition, not a code change (AD-15,18).
- (constraint) Meter Reading entry must work offline (local queue, sync on reconnect) — meter locations are frequently signal-weak; a flaky retry must never double-insert a reading (AD-16).
- (constraint) Edits to configuration inputs (Yearly Baseline, threshold, normalization formula) affect calculations going forward only — historical computed values are never silently rewritten by a later settings change (AD-7).
- (constraint) Concurrent writes to the same Household's data never silently lose an update — reject-and-retry via optimistic concurrency, never last-write-wins or a silent merge (AD-4).
- (constraint) Corrections to a Meter Reading or Tariff entry preserve the original value as a visible note rather than a silent overwrite (AD-11).
- (constraint) The dashboard Status is the product's headline surface; drill-down views (trend, per-plug data) existing is fine, but nothing may make checking them a precondition for trusting the Status — 'says less, on purpose.'
- (non-goal) Not real-time/near-real-time monitoring — manual-read and file-upload driven by design, not a live dashboard.
- (non-goal) Not a hosted/managed offering — self-deploy only.
- (non-goal) Not an automated room-by-room energy-audit/attribution tool — the precision claim v1 walked back is not repeated in v2.
- (non-goal) Not a native mobile app; not a cross-user admin/management platform — multi-user is possible but the product isn't designed around managing users.
- (non-goal) Not a market-percentile tariff ranking service (needs a third-party data feed); not a general plugin marketplace — the three Extension Points are scoped, not open-ended.
- (non-goal) Not a general life-logging tool — Context Capture is scoped to unmeasurable-appliance energy events only; not a general billing engine — flat base-fee-plus-price/kWh tariffs only, tiered/time-of-use billing out of scope.
- (non-goal) Not multi-Main-Meter UI/logic in v2 (data model allows it, Pattern Detective/dashboard operate on one per Household); not a v1-to-v2 data migration — ground-up rebuild, no migration path.
