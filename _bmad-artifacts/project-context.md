## Technology Stack & Versions

**Backend:** .NET 10 (LTS to Nov 2028), ASP.NET Core 10 Minimal APIs, EF Core 10.
**Frontend:** React 19.2, Vite 8.2, TypeScript ~6.0, Tailwind CSS v4, shadcn/ui + Radix.

**Key dependencies:**
- Persistence: Npgsql.EntityFrameworkCore.PostgreSQL 10.0.3 (Postgres 17 self-host) / Microsoft.EntityFrameworkCore.SqlServer 10.0.12 (Azure SQL Basic DTU) — dual-provider, config-selected.
- Auth: Microsoft.AspNetCore.Authentication.OpenIdConnect 10.0.12 + cookie auth, Microsoft.AspNetCore.DataProtection.EntityFrameworkCore 10.0.12, Azure.Extensions.AspNetCore.DataProtection.Keys 1.6.4 + Azure.Identity 1.21.0 (both pinned explicitly in `Directory.Packages.props`, referenced by Api project; Key Vault protector for Data Protection key ring, AD-17; `Azure.Identity` also arrives transitively via `Microsoft.Data.SqlClient`).
- Observability: Serilog.AspNetCore 10.0.0, OpenTelemetry.* 1.19.x (`OpenTelemetry.Instrumentation.EntityFrameworkCore` pinned to `1.19.1-beta.1` deliberately — no stable release upstream).
- .NET testing: xunit.v3.mtp-v2 3.2.2, Shouldly 4.3.0, NSubstitute 6.2.0, Testcontainers.PostgreSql/MsSql 4.15.0, Microsoft.AspNetCore.Mvc.Testing 10.0.12.
- Frontend: i18next 26.x + react-i18next 17.x, class-variance-authority, tailwind-merge, lucide-react.
- Frontend testing: Vitest 4.1, @testing-library/react 16.3, @playwright/test 1.62, oxlint 1.75 (not ESLint).

**Version constraints:**
- SDK pinned via `global.json` to `10.0.100`, `rollForward: latestFeature`.
- All NuGet versions centrally managed in `Directory.Packages.props` (`ManagePackageVersionsCentrally=true`) — never add `Version=` to `<PackageReference>` in `.csproj`; bump version in `Directory.Packages.props` instead.
- EF Core packages (EFCore, EFCore.Design, EFCore.Relational, EFCore.SqlServer) pinned to identical `10.0.12` line to avoid transitive version conflicts — bump together, never individually (`dotnet-ef` tool in `.config/dotnet-tools.json`, `Microsoft.AspNetCore.DataProtection.EntityFrameworkCore`, `OpenIdConnect`, `Mvc.Testing`, `Microsoft.Extensions.Logging.Abstractions` ride same patch). OpenTelemetry packages move together on one 1.x line too.
- `xunit.v3.mtp-v2` runs on Microsoft.Testing.Platform (`global.json` `test.runner`), not classic VSTest runner — test invocation differs from xUnit v2 projects.

## Critical Implementation Rules

### Language-Specific Rules

**C# (nullable/implicit usings enabled across all projects):**
- File-scoped namespaces, primary constructors for DI (e.g. `public class CreateDevice(ITaggingScaffoldRepository repository)`), one use-case class per file — no feature-folder nesting under `Application/` (flat: `CreateDevice.cs`, `ArchiveRoom.cs`, etc.).
- Use cases named imperative verbs (`CreateHousehold`, `RenameDevice`, `AcceptHouseholdInvite`) with single `ExecuteAsync(...)` method — not generic `Handler`/CQRS mediator pattern.
- Validation throws typed domain exceptions (`TaggingScaffoldValidationException`, `HouseholdValidationException`, `*NotFoundException`, `*ArchivedException`) rather than return result objects or throw generic `ArgumentException`.
- `Nullable` and `ImplicitUsings` are `enable` — don't add explicit `using System;` etc., treat nullable warnings as real (no `!`-suppressing without reason).
- Ports live in `Application/Ports` named `I{Capability}`; adapters live in `Infrastructure/Adapters` named `{Vendor}{Capability}` — never place interface and implementation in same project.
- **AD-1 (Ports & Adapters direction):** Domain has zero external package refs beyond BCL. Application defines interfaces only — never references `Infrastructure` or `Api`. All framework/vendor packages live in `Infrastructure`/`Api`. Enforced by `tests/EnergyTracker.Architecture.Tests` (`DomainHasNoExternalDependenciesTests.cs`) — violation fails test suite, not just convention.

**TypeScript/Frontend:**
- `verbatimModuleSyntax: true` — type-only imports must use `import type { Foo }`, not plain `import { Foo }` that gets erased.
- `noUnusedLocals` + `noUnusedParameters` + `erasableSyntaxOnly` on — unused bindings and non-erasable TS syntax (e.g. enums, parameter properties) fail build (`tsc -b`).
- Path alias `@/*` → `web/src/*` — use `@/components/...` imports, not relative `../../` chains, for anything outside same folder.
- Linting is **oxlint**, not ESLint — don't propose `.eslintrc` config or ESLint-specific rule names.
- `allowImportingTsExtensions` + `noEmit` — bundler-mode (Vite) TS setup; don't assume CommonJS/`tsc`-emit conventions.

### Framework-Specific Rules

**ASP.NET Core / EF Core (backend) — architecture-spine invariants, not preferences:**
- **Config-driven adapter selection:** every swappable capability (DB provider, job queue, AI backend, OIDC) selected by exactly **one** config value read once at composition root (`Program.cs`). No feature code branches on environment or provider elsewhere.
- **Tenant isolation (AD-3):** every Household-scoped entity carries `HouseholdId`; `EnergyTrackerDbContext.OnModelCreating` applies global query filter from `ICurrentHouseholdAccessor`. Never write per-handler/per-repository household filtering, never use `DbSet<T>.Find()`, `FromSqlRaw`, or `.IgnoreQueryFilters()` against Household-scoped entity — that's the bypass this rule exists to close.
- **Household resolved once per request, asynchronously (Story 11.12, audit C2):** `HouseholdMembershipMiddleware` (`UseHouseholdMembership()`, registered in `Program.cs` after `UseExceptionHandler`, `UseAuthentication`, `UseAuthorization`, `UseRateLimiter` and before first endpoint) looks caller up through `HouseholdMembershipResolver` (`SingleOrDefaultAsync` on `IDbContextFactory<HouseholdMembershipDbContext>.CreateDbContextAsync`, issuer from `HouseholdClaimTypes.ValidatedIssuer`) for authenticated request under `/api` only, stores `ResolvedHouseholdMembership` in `HttpContext.Items` (principal with no row stored as "none" too). `CurrentHouseholdAccessor` only reads it (constructor: `IHttpContextAccessor` and `JobHouseholdContext`, nothing else; lazy, because Data Protection builds it inside `UseAuthentication`): no synchronous lookup, no cross-request cache, nothing in cookie or claims (AD-17/AD-26: removed member's next request resolves nothing). Without `HttpContext` it takes job path (`JobHouseholdContext`, unchanged). Authenticated principal with no cached value makes it throw `InvalidOperationException` naming `UseHouseholdMembership` (never silent fallback or "no Household"), so new authenticated route **outside `/api`** needing Household must be covered by middleware first. Membership changes inside request not visible until next one (create, accept, remove do not read accessor after write). `HouseholdMembershipIsResolvedOncePerRequestTests` guards accessor, the one place that opens membership context, claims, registration order; `HouseholdMembershipIsResolvedPerRequestTests` counts lookups on real host (its factory decorator throws on synchronous `CreateDbContext()`).
- **Dual-provider persistence (AD-2):** one shared `EnergyTrackerDbContext`, never per-provider subclass. Only portable relational subset (`string`, `int`, `decimal`, `DateTimeOffset`, `bool`, `byte[]`, standard LINQ) — no Postgres `jsonb`/`ILike`, no SQL Server `rowversion`, no provider-specific column mapping. Migration added to **both** provider projects in same commit via `scripts/add-migration.sh <Name>`, never to one alone.
- **Optimistic concurrency (AD-4):** concurrency-sensitive entities (Meter Reading, Tariff, Household settings) carry plain `int Version` EF concurrency token — never provider-specific mechanism (`rowversion`/`xmin`). Conflicts throw `DbUpdateConcurrencyException` → HTTP 409 with current server state; never last-write-wins or silent merge.
- **Compute-at-request-time vs. persisted history (AD-7):** current Status/Reminder are pure synchronous computations on every read — never precomputed by background schedule (`IHostedService`/`Timer` doesn't survive scale-to-zero). Every time Status recomputed, also written to immutable `StatusSnapshot` row via the **one** `IStatusRecomputeService` — don't build second snapshot writer. History reads (Trend History) always read persisted `StatusSnapshot`, never live recompute.
- **Async jobs (AD-6):** one `IBackgroundJobQueue` port, payload always plain JSON-serializable record (`JobEnvelope<TPayload>`) — never delegate/closure-based executor. Clients learn job finished by **polling** `GET /api/jobs/{id}`, never WebSocket/SSE. Every `BackgroundJob` status change goes through `IBackgroundJobLifecycle` (one conditional update, `StartedAtUtc` ownership token; stale/interrupted jobs fail as `job-interrupted`) — never assign `Status` elsewhere; `BackgroundJobStatusHasOneWriterTests` enforces.
- **Main Meter is sole authoritative total (AD-14):** no domain code, service, DTO, or frontend view may sum `SmartPlugReading`/`Event` data into figure compared against or rendered alongside Main Meter total. No `Residual` type/field/DTO/view anywhere.
- **No hardcoded household-specific values (AD-15):** every household-specific value (baselines, thresholds, currency, locale) is `Household`-scoped config row, never literal in code.
- **Idempotent Meter Reading writes (AD-16):** creation carries client-generated idempotency key (GUID) set before any network attempt; API upserts by that key.
- **Auth (AD-17):** cookie auth chained to OIDC — SPA never reads or stores token itself. Data Protection keys persist via `PersistKeysToDbContext`, never in-memory default (doesn't survive scale-to-zero). Key ring must be encrypted at rest: Azure Key Vault (`DataProtection:KeyVaultKeyId`, Container App managed identity) on Azure, certificate (`DataProtection:CertificateBase64`) or explicit opt-out (`DataProtection:AllowUnprotectedKeys=true`) elsewhere, chosen once by `DataProtectionKeyProtection` at composition root. **Fail closed:** outside Development with none of three, app refuses to start; any new test host running outside Development sets opt-out. Key Vault wins over certificate; Development with nothing configured stays unprotected and warns. **Session lifetime (Story 11.8, S13):** explicit 14-day sliding window plus 90-day absolute cap (`SessionLifetime.cs`): issued-at stamp written into ticket's `AuthenticationProperties.Items` at sign-in (`OnSigningIn`, not on renewal; never `IssuedUtc`, which restarts on renewal) and `OnValidatePrincipal` rejects and signs out cookie with no stamp, unreadable stamp, or stamp 90 days old. Cookie without stamp rejected on purpose (no grandfathering), so deploying this signs everyone out once. Clock is `TimeProvider` from DI.
- **Member trust and invites (AD-26, Story 11.9, audit A2/S10):** every member has full, equal trust; no roles, no endpoint may invent Owner or admin check. Removing member and leaving are one route (`DELETE /api/household-members/{id}`, id is caller's own when leaving) and one `SaveChanges` in `HouseholdRepository.RemoveMemberAsync`: deletes membership, expires every open invite, bumps `Household.Version`, which is race guard (last-member count only friendly error). `HouseholdMember` and `HouseholdInvite` are AD-3 query-filter exceptions, so every by-id access carries explicit `HouseholdId`: the one by-id member lookup is `FindMemberInHouseholdAsync`, and `HouseholdMemberLookupsAreHouseholdScopedTests` fails for new file that queries either set, a bypass (`Find`, `IgnoreQueryFilters`, `FromSql`), or by-id access without `HouseholdId`. Revoking invite sets `ExpiresAtUtc` to now (no column). Invite tokens are 32 random bytes as base64url, only SHA-256 hash stored (`TokenHash`); `InviteToken` is only place that generates or hashes token, lookup tries hash first, legacy plaintext `Token` column second (dropped in later release, see `deferred-work.md`). Open-invite list never returns token or hash, no exception message, log line, or response may carry presented token. Removed member's cookie stays valid but resolves no Household on next request (AD-17 amendment), so they land in household creation; their already-open tab keeps stale `ready` state, and `HouseholdMemberEndpointsTests` sweeps every `/api` route as removed member and fails if any answers 2xx (add new routes with usual no-Household 403 check). The two `DELETE` routes carry `RateLimitPolicies.MemberRemoval`.
- **HTTP hardening (AD-27, Story 11.7):** outside Development hand-written middleware (`SecurityHeaders.cs`, registered **first**) sets CSP (`script-src 'self'`, `style-src 'self' 'unsafe-inline'` for Radix, `form-action 'self'`, `frame-ancestors 'none'`, `img-src 'self'`), `nosniff`, `Referrer-Policy: same-origin` in `Response.OnStarting` (set before `next()` they are lost on 500, because `UseExceptionHandler` resets response); `UseHsts()` follows `UseForwardedHeaders`. `web/index.html` carries no inline script (guarded by `IndexHtmlHasNoInlineScriptTests`); pre-paint theme script is `web/public/theme-init.js`. **CSRF (Story 11.8, S9):** every POST/PUT/PATCH/DELETE under `/api` needs `X-Requested-With` header, enforced by one endpoint filter on `/api` group (`RequestedWithFilter.cs`, `RequireRequestedWith()`; presence only, SPA sends `fetch`); `POST /logout` carries filter explicitly. Filter adds marker (`RequestedWithRequiredMetadata`) and `RequestedWithRoutesTests` fails for any mutation route without it, so new route cannot ship unprotected. Endpoint filters run after parameter binding, so body that fails to bind answers binding's 400 first. Rate limiting is built-in in-process limiter (`HttpRateLimiting.cs`, `UseRateLimiter` after `UseAuthorization`): policies per route via `RequireRateLimiting`, identity-keyed (issuer + subject) except `/login` (client IP); limits are table in Story 11.7, and `RateLimitedRoutesTests` fails when new upload/export/invite route not classified. Forwarded headers stay untouched (Story 1.7); deploy's health gate probes `/health` only, so CSP regression caught only by local Production rehearsal in Chrome and live check, never by pipeline.
- **Uploads streamed and bounded (Story 11.10, audit S4):** never read upload into one string or array. `POST /api/household-import` copies file to temp file and validates from that `FileStream` with `HouseholdImportJsonReader` (`Utf8JsonReader`, two passes; buffer capped 4 MiB, 200 failures, 100 member names of 200 characters), and `RestoreHouseholdData` deserializes from stream; `HouseholdImportIsStreamedTests` fails on `ReadToEnd`, `ReadAllText`, `ReadAllBytes`, `JsonDocument.Parse(`, whole-export `Deserialize` or `new StreamReader(` in those files. Temp file deleted on every path not ending in successful `Register` (one `try/finally` in `ReceiveUploadAsync`). Registry holds at most one pending upload per Household (replacement at `Register` of new validated one, atomic under one lock, never touching consumed token's file) and `Consume` deletes file of expired or wrong-Household entry. XLSX package opened in exactly one place, `EveHomeXlsxParser.OpenDocument`: decompressed-size pre-scan (64,000,000 bytes total across all entries, real bytes counted, cancellable, entries .NET cannot inflate and directory entries skipped), `OpenSettings.MaxCharactersInPart` as backstop, 400,000-row cap in `Parse`, rows read cell by cell with 100-cell cap (row never loaded whole); limits throw `SpreadsheetTooLargeException`, which `BackgroundJobProcessor` maps by type to `spreadsheet-too-large` (translated in both locales). Restore job still materializes whole object graph; see `docs/data-import-restore.md`.
- **Config correctness (Story 11.11, audit S7/C11/C1):** `ConnectionStrings:Default` required outside Development: unset, empty or whitespace stops host with message naming `ConnectionStrings:Default`/`ConnectionStrings__Default` (never configured value), only Development falls back to local `change-me` string (check runs before Data Protection one; `ConnectionStringStartupTests` pins it, any new test host outside Development sets the setting). `/login` answers 503 `application/problem+json` "Sign-in is not configured" when OIDC unset (rate limiter still applies on both branches). AI backend configured **only** through `Ai:Endpoint`, `Ai:ApiKey`, `Ai:Model`, `Ai:BackendLabel`, read once in `AiPlausibilityBackendConfiguration` (no `AiPlausibility:*` fallback): blank endpoint is no-op client, set endpoint not absolute http(s) URL fails startup, startup log names adapter and never key, and `AiConfigurationKeysAreOneSetTests` fails when code, `appsettings.json`, `.env.example`, `docker-compose.yml`, `scripts/run-api.sh`, Bicep env block stop naming same four keys.
- **One active instance (AD-24, Story 11.13, audit A1):** app correct only with exactly one instance; `maxReplicas` stays `1` in `container-app.bicep`, `main.bicep`, `main.bicepparam`, raising it is architecture decision, not config change. Seven process-local mechanisms bound by it (upload registry, per-Household recompute lock, temp-file job payloads, in-process Channel queue, AD-6's startup sweep, upload-registry expiry sweep, in-process rate limiter); each keeps one-line `AD-24` comment instead of re-arguing, and `docs/self-hosting.md` ("Run exactly one instance") lists them. New `ConcurrentDictionary<`, `SemaphoreSlim`, `Channel.Create`, `IMemoryCache`, `AddRateLimiter` or `Path.GetTempPath` in `src` fails `SingleInstanceInvariantIsDocumentedTests` until listed, commented, documented. `InstanceHeartbeatService` observes invariant: writes own `AppInstances` row every minute, logs one warning per other instance that overlapped it more than 15 minutes; never blocks startup, never touches `/health`, never lets exception escape `ExecuteAsync`, nothing reads table except that log line (AD-7). `AppInstances` is AD-3 exemption (no `HouseholdId`, no query filter, not exported or restored), like `HouseholdMember`, `HouseholdInvite`, `DataProtectionKeys`.
- **Restore re-keys, one active restore or cleanup per Household is database index (Story 11.14, audit C10, AD-6):** `RestoreHouseholdData` gives every restored entity new `Guid` id and every meter reading new `IdempotencyKey` (`HouseholdRestoreRekey`, pure, in Application, built from deserialized file) and rewrites every reference, including two without foreign key (`Event.TaggedEntityId` by `TaggedEntityType`, `AuditCorrection.EntityId` by `EntityType`); reference resolving to nothing in file kept as is. Ids in backup are file-local names, never stable identifiers, so nothing may persist one across restore. Filtered unique index `UX_BackgroundJobs_ActiveExclusive` on `BackgroundJobs (HouseholdId, JobType)` covers `JobTypes.ExclusivePerHousehold` (`RestoreHouseholdData`, `CleanUpSmartPlugImportJobs`) while `Status` is `Queued` or `Processing`; raw SQL in two `AddActiveJobGuard` migrations only, must never become `HasFilter` in shared model (AD-2). `BackgroundJobEnqueueRecorder` turns rejected insert into `ActiveJobAlreadyExistsException` (probe for active row, no provider error codes), which restore-confirm answers `409` and cleanup answers `202` with existing job id; early checks stay as fast path. `ActiveJobGuardIsDeclaredTests` fails for changed index, filter or unique index in `BackgroundJobConfiguration`, second thrower, or new `BackgroundJobStatus` nobody classified active or terminal; `HouseholdRestoreRekeyTests` and C10 cases in `HouseholdRestoreWriterTests` cover re-key.
- **Time injected, recompute lock evicts (Story 11.17, audit C5/C6):** Application and Infrastructure code (and the one Api endpoint needing it) read clock only through injected `TimeProvider` (`timeProvider.GetUtcNow()`, registered once as `TimeProvider.System` in `Program.cs`); `NoDirectClockReadsTests` fails on `DateTimeOffset.UtcNow`/`Now`, `DateTime.UtcNow`/`Now`/`Today` or `TimeProvider.System` anywhere in `src` outside `Program.cs` (comments stripped, `Migrations` excluded). Domain never reads clock: calculation takes `now` as parameter (`SmartPlugGapDetector.DetectGaps`). Keep number and order of clock reads per operation as were (`now` is data point, `BackgroundJobLifecycle`'s token truncated to whole milliseconds, `InProcessChannelJobProcessingService` captures start once at construction). Tests use `tests/Shared/ManualTimeProvider.cs` (`Advance`, `Set`; linked into Application, Infrastructure, Api test projects), never `FakeTimeProvider` package, never `Task.Delay` to make time pass. `HouseholdRecomputeLock` reference-counts per-Household entries (holders plus waiters, one `lock`, never held across `await`) and removes idle entry; timeout and cancellation paths return their reference, so dictionary bounded by Households in use, not Households ever seen (AD-24 still applies: lock process-local).
- **Trending threshold annual (Story 11.15, audit C12, FR-6):** `Household.TrendingThresholdKwh` is kWh per year; `PatternDetectiveCalculator.ResolveStatus` takes annual value plus pace window's `Elapsed` and scales it with `BonusDecayNormalizer.NormalizeToDate`, so first-year household reaches *Trending* at same relative overshoot as after a year; scaling is `TrendingThreshold.ScaleToDate` (normalizer's proration, floored at one meter step, 1 kWh, never above annual figure, so day or two of readings cannot be decided by rounding noise; `WindowedDeviationCalculator` calls it too); *below baseline* still any shortfall and tie is *within range*. `CurrentStatusResult.TrendingThresholdToDateKwh` and detail response's `trendingThresholdToDateKwh` carry figure that decided Status; snapshots never rewritten (AD-7).
- **Single deployment artifact (AD-13):** `Api` project serves built SPA from `wwwroot/` — don't introduce separate static-hosting deployment path.
- **Operational baseline (AD-19):** `/health` liveness-only (no DB check). Logging structured (Serilog) to stdout/stderr only, no environment branching in logging code. Secrets only via env vars/Container Apps secrets/`.env` — never committed or baked into image.

**React (frontend):**
- **i18n (AD-18):** `Household.Locale` is single field driving both number/date formatting and UI language; translations are additive i18next catalogs in `web/src/locales/{locale}` — adding locale is resource-file addition, never code change.
- **Offline queue (AD-16/stack):** Meter Reading creation only (not edits) queues locally via IndexedDB and flushes on reconnect — don't extend this offline pattern to other writes without matching architecture decision. **Reading server permanently refuses is kept, never deleted (Story 11.16, audit C4):** `flushQueue` marks 4xx answer (except 401, 403, 408, 429, which are transient like 5xx and network failure) on entry itself (`QueuedMeterReading.rejection`: status, server's `detail`, timestamp; no store or `DB_VERSION` change), skips marked entries from then on, and Dashboard shows them in one quiet card under Status card (`RejectedReadingsCard`, fed by `useRejectedReadings`, which re-reads on `QUEUE_CHANGED_EVENT`, dispatched after every committed write) until member corrects and resends (`resendRejectedReading`: same `idempotencyKey`, no parameter for key) or discards it. Entry and `rejection` are one read-modify-write in one transaction and missing key never created. `listPending()` returns every entry on purpose (logoff and leave count them, `removeForHousehold` deletes them); use `listNeedsAttention(householdId)` for rejected ones.
- **Visual reordering must not reorder focus (WCAG 2.4.3):** `wide:order-*`, `flex-row` pairs, grids may only rearrange content so Tab order still equals reading order. `web/e2e/tab-order.spec.ts` enforces per surface. No exceptions: NavChrome's two placements (`top` first in `<main>`, `bottom` last) mounted separately precisely so no CSS `order` needed, spec guards it. Add any new reordered surface to that spec.
- **Breakpoint and column width have guarded copies:** `--breakpoint-wide` (index.css) is breakpoint's source; `web/src/layout-constants.drift.test.ts` fails and names stale copies of px-valued breakpoint (hook `WIDE_QUERY`, `min-width: Npx` stubs and assertions, e2e 600-699 literals) and of column (`wide:max-w-[Cpx]` wrappers vs `app-shell.spec.ts` column assertions). To change breakpoint, edit `--breakpoint-wide` first and let test list other copies; column has no single source, so change all copies together. Other forms (rem, `max-width`, `min-[…]:` variants) not scanned.
- **All HTTP goes through `web/src/lib/api-client.ts` (Story 11.8, AD-27):** `apiFetch` adds `credentials: 'include'` and `X-Requested-With` header API requires on every mutation; `ApiError` and `toApiError` live only there, no re-exports, no per-feature copies. `FrontendUsesTheSharedApiClientTests` fails on bare `fetch(`, second `ApiError`/`toApiError` or `credentials: 'include'` anywhere else under `web/src`. `apiFetch` returns raw `Response` and never throws on non-2xx status; call sites branch on `status` themselves.
- Components follow existing `web/src/components/{feature}` grouping (e.g. `household-invite`, `household-creation`, `tagging-scaffold`) plus shared `components/ui` for shadcn primitives — new feature UI gets own folder, not dumped into `components/ui`.

### Testing Rules

**.NET tests:**
- Test class per subject, named `{SubjectClass}Tests` (`CreateDeviceTests` for `CreateDevice`), one file per class, mirrored 1:1 into `{Layer}.Tests` (e.g. `EnergyTracker.Application` → `EnergyTracker.Application.Tests`).
- Test methods use `Snake_case_with_underscores` describing behavior (`Creates_and_persists_an_active_device_on_the_power_point`) — not `MethodName_Scenario_ExpectedResult` or camelCase.
- Assertions use **Shouldly** (`.ShouldBe(...)`, `Should.ThrowAsync<T>(...)`) — never raw xUnit `Assert.*`.
- Mocking uses **NSubstitute** (`Substitute.For<IPort>()`, `.Returns(...)`, `.Received(1)...`) against Application ports — never hand-rolled fake/stub class.
- Async tests pass `TestContext.Current.CancellationToken` (xUnit v3 MTP convention) — not `CancellationToken.None` or `default`.
- Integration-level tests (migrations, DB-touching) use **Testcontainers** (real Postgres/SqlServer containers, not in-memory EF provider) — AD-2's dual-provider portability only verifiable against real engines.
- **Database tests share one server per provider (spec-ci-pipeline-runtime-speedup).** New Infrastructure or Api test class takes `PostgresTestDatabase` / `SqlServerTestDatabase` (`tests/Shared/SharedDatabaseServers.cs`, linked into both test projects, one shared Postgres/SQL Server container per test assembly); `IAsyncLifetime` on class creates and drops one empty database on it, class still migrates itself. Never `new PostgreSqlBuilder(...)`/`new MsSqlBuilder(...)`, which starts container per test method and was 9 of 13 minutes of deploy. One exception: test that creates server-wide login (`...MinimalSqlServerPermissionsTests`). `TestsShareDatabaseServersTests` enforces.
- `EnergyTracker.Architecture.Tests` encodes spine invariants as executable tests — when adding new AD-style invariant, consider whether it belongs here as guard test, not just prose.

**Frontend tests:**
- Unit/component tests colocated next to source (`color-scheme.test.ts` next to `color-scheme.ts`) — not parallel `__tests__/` tree.
- Vitest + Testing Library (`@testing-library/react`), `jsdom` environment, globals on.
- E2E tests live in `web/e2e/*.spec.ts` via Playwright (`test:e2e`) — separate from Vitest unit-test path (`test`/`test:watch`).

### Code Quality & Style Rules

**Naming:**
- Entities/DTOs: PascalCase C#, singular (`MeterReading`, never `MeterReadings`).
- API routes: kebab-case plural nouns (`/api/meter-readings`).
- Ports: `I{Capability}` in `Application/Ports`; adapters: `{Vendor}{Capability}` in `Infrastructure/Adapters`.

**Data & format rules (apply everywhere, not just entity boundaries):**
- All timestamps `DateTimeOffset`, ISO 8601 with explicit offset on wire — never bare `DateTime`.
- All money `decimal`, never `double`/`float`. Currency is ISO 4217 code stored per Tariff entry.
- Background/scheduled work runs in UTC regardless of display Locale — locale only affects display, never storage.

**Errors:**
- API errors are RFC 7807 `ProblemDetails` — no ad hoc error shapes or bare status codes with string body.
- Concurrency conflicts return HTTP 409 with current server state (AD-4), not generic 400/500.

**C# documentation:**
- Public use-case classes get single-line `/// <summary>...</summary>` stating what they do and which acceptance criteria they satisfy (e.g. `Creates a Device on a Power Point in the caller's own Household (AC #1, #4).`) — not multi-line XML doc blocks or `<param>`/`<returns>` tags for straightforward cases.

**shadcn/ui config (`web/components.json`):**
- Style `radix-nova`, base color `neutral`, icon library `lucide`, no `tailwind.config` file (Tailwind v4 CSS-first config lives in `src/index.css`) — don't scaffold `tailwind.config.js`/`.ts`.
- Aliases: `@/components`, `@/components/ui`, `@/lib`, `@/lib/utils`, `@/hooks` — prefer `npx shadcn add` over hand-writing primitives already existing as shadcn components.

**oxlint (`web/.oxlintrc.json`):**
- `react/rules-of-hooks` and `no-unused-vars` are `error` (build-breaking); `react/only-export-components` is `warn` with `allowConstantExport: true`.

### Development Workflow Rules

**Git/commits:**
- Commit messages use Conventional-Commits-style prefix (`feat:`, `fix:`, `doc:`) followed by concise imperative summary.
- Branch naming: `feature/{short-description}` (e.g. `feature/otel-integration`).
- Commits/PRs often reference AD number or story number implemented — carry traceability forward when change maps to spine decision or story file.

**CI (`pr-review.yml`):**
- Runs on every PR against `main`: builds/tests/lints .NET solution and web frontend; runs infra `what-if` only when `infra/**` changed and PR not from fork. Never deploys — deploys only from `app-deploy.yml`/`infra-deploy.yml` on push to `main`.
- **`app-deploy.yml` is four jobs (spec-ci-pipeline-runtime-speedup):** `frontend-tests`, `backend-tests`, `image-build` run in parallel, `deploy` needs all three. Only `deploy` logs in to Azure (job-level `id-token: write`, none at workflow level), migrates, pushes, rolls out; `image-build` builds with `push: false` and exports Actions layer cache (`scope=app-image`) that `deploy`'s "Build and push image" reads via `cache-from`. `AppDeployWorkflowJobsGuardTests` pins `needs` list and keeps Azure, secrets, `push: true` out of other three; preflight and restore-point guards read steps of `deploy`. "Ensure ACR pull credential and target port" skips its two writes when live app already has system identity for registry and target port 8080.
- **Two Azure identities (Story 11.5, audit S11):** `pr-review.yml`'s `validate-infra` logs in as read-only `energy-tracker-pr-reader-uami` (Reader plus custom `Energy Tracker PR What-If` role, because Reader alone denied what-if call) (`AZURE_PR_CLIENT_ID`, `pull_request` credential, what-if with `--validation-level ProviderNoRbac`); Owner-scoped deploy identity (`AZURE_CLIENT_ID`) reachable only from `main`. Never give PR identity write or key-listing right; rights and probes in `infra/README.md` ("Workflow identities and their permissions").
- **Preflight:** each Azure-authenticated workflow runs `Preflight: identity permissions` (`scripts/ci/azure-preflight.sh <mode>`) before any step that changes something; `WorkflowPreflightGuardTests` enforces order.
- **Actions pinned to commit SHA with `# vX.Y.Z` comment** (`WorkflowActionsArePinnedToCommitShaTests`). Dependabot GitHub Actions PRs never auto-merged: read SHA diff, merge by hand. CodeQL (`codeql.yml`) and image scan (`container-scan.yml`) are separate workflows with no secrets, not required checks.
- **Image (Story 11.11, audit S5):** runtime stage runs as `USER $APP_UID` (aspnet image's non-root `app`, 1654; files stay root-owned, process writes only `/tmp`), and build stage copies `global.json` and `Directory.Build.props` before `dotnet restore`, so NuGet-audit gate and SDK pin apply to shipped image. `DockerImageMatchesTheVerifiedBuildTests` guards both and fails on later `USER root`/`USER 0`.
- **Registry retention (spec-acr-image-retention):** `acr-retention.yml` (Sundays 01:00 UTC, or by hand with `dry_run` input) keeps 7 newest `energy-tracker` images in Basic ACR with `acr purge` as ACR Task (built-in retention policy Premium-only). Runs as deploy identity from `main` after `retention` preflight, in own concurrency group (not `infra-app-deploy`, whose single pending slot purge could take from queued deploy), refuses to run when running image not among 7 newest tags, sweeps orphaned manifests only when older than an hour. Never `continue-on-error` it, never add `push`/`pull_request` trigger, never `--include-locked`; `AcrRetentionWorkflowGuardTests` enforces. Rollback target must be one of last 7 images.
- **Node:** CI's `node-version` must match Dockerfile's frontend stage (`node:26-alpine`); change both together. Vitest config turns off Node's built-in `localStorage` (`--no-experimental-webstorage`) because it shadows jsdom's.
- `npm audit --omit=dev --audit-level=moderate` gates `build-test-lint` like NuGet Audit gate below.
- `build-test-lint` job has **no `name:` override** — GitHub branch protection matches required status checks by job id, not display name.
- Workflow-level `concurrency` cancels in-progress runs on new pushes to same PR.
- **NuGet Audit gate (`Directory.Build.props`):** `NuGetAuditMode=all` + `NuGetAuditLevel=moderate` + `NU1902`–`NU1904` in `WarningsAsErrors` — moderate-or-worse advisory on direct **or transitive** package fails `dotnet restore` (`build-test-lint` job's first step), not just warns. Don't suppress NU190x code to unblock PR — bump/replace offending package (see `spec-nuget-audit-ci-gate.md`, `spec-ssh-net-cve-fix.md`).
- **Backend analyzer gate (Story 11.18, audit R3):** `Directory.Build.props` sets `AnalysisMode=Recommended` + `AnalysisModeSecurity=All` (SDK analyzers, no package). Warnings fail only in CI: `pr-review.yml` builds with `-p:TreatWarningsAsErrors=true` (NU1900 exempt) and runs `dotnet format EnergyTracker.sln --verify-no-changes --no-restore`; Docker image and `app-deploy.yml` stay warnings-only. Lower a rule only with a `#` comment line directly above the `.editorconfig` line, or a `[SuppressMessage(..., Justification = "...")]` on the member. Never `#pragma warning disable`, never `<NoWarn>`. EF migrations are `generated_code = true` in `.editorconfig`. Test names keep `Snake_case` because `CA1707` is off for `tests/**`. Guard: `BackendAnalyzerGateIsConfiguredTests`. Run `dotnet format EnergyTracker.sln` before pushing.

**`_bmad-artifacts/implementation/deferred-work.md` convention:**
- **Append new sections at end of file, chronological order (oldest first, newest last).** Never insert at top. Matches what `bmad-code-review` skill does; Epic 8 retro found mixed insertion order (newest-first sections interleaved with appended ones) was main reason file became hard to read (519 lines, ~58 sections). Each section keeps heading `## Deferred from: code review of <story-or-spec> (<YYYY-MM-DD>)`. Traces to Epic 8 retro (2026-10-02, Action #5).
- **Every entry starts with status marker:** `[open]`, `[resolved: <story-or-spec>]`, or `[accepted: <reason, plus revisit trigger if any>]` (`[promoted: needs story]` while promoted item has no story yet). New entries written `[open]`. When entry resolved or accepted, move out of `deferred-work.md` (resolved: delete; accepted: move to `deferred-work-accepted.md`) instead of leaving it. Review open items, and themed index at top of file, at each epic retro. Traces to Epic 8 retro (2026-10-02, Action #7); 2026-10-02 triage (`spec-deferred-work-triage.md`) established two-file split.

**Migrations:**
- Always add migrations via `scripts/add-migration.sh <Name>` — never `dotnet ef migrations add` directly against one provider project (AD-2).
- **Expand/contract:** migration must be safe for **previous** application image to run against. `app-deploy.yml` migrates before deploying, and its health-check rollback redeploys previous image against already-migrated schema; failed multi-migration run can also stop partway. Destructive changes (drop/rename column or table, narrowing `AlterColumn`, new NOT NULL without default) ship in **later** deploy than code that stops using old shape.
- Rollback is point-in-time restore, not `Down()`: every deploy writes "Pre-migration restore point" block to Actions run summary; procedure is `infra/README.md` → "Rolling back a bad migration".

**Local dev scripts (`scripts/`):** `run-api.sh`, `migrate.sh`, `add-migration.sh` — prefer over raw `dotnet run`/`dotnet ef` invocations; encode required env vars and provider wiring documented in `docs/local-development.md`.

### Critical Don't-Miss Rules

**Process gates (hard, no exceptions):**
- **No fix to already-shipped code merges without linked spec/story doc, regardless of size or urgency.** Write at least minimal `spec-*.md` (or story stub) before or as part of fix — never skip because fix trivial or incident pressure, since that's exactly condition under which skipped before. Hard gate at PR merge, no exceptions. Traces to 2026-09-11 Epic 4 retro (PR #40/#41 shipped production-surfaced integration fixes with zero spec/story trail); recurred at smaller scale afterward (`1b1960c`, `ee178cc`, `b40902a` — CI/test-flakiness fixes merged straight to `main` with no linked spec).
- **Story touching OIDC claims, auth flows, or any other browser-dependent behavior cannot move review→done without live Auth0/Chrome verification actually performed.** If Chrome unavailable, story stays blocked in review — never mark live-verification task complete on strength of unit/component test alone. Raise "not connected" Claude-in-Chrome extension immediately and pause for user to start/connect it, then resume — don't silently defer check and let code review catch gap after the fact (Epic 6 Retro Action Item #1 sharpened this to dev-story-time gate after Story 6.2's Task 7 got checked off without actual live run for AC #5, caught only in review). Traces to 2026-09-11 Epic 4 retro (3.5/3.6/4.1/4.2 all deferred live verification with no follow-up; the one time checked, 3.6, it found real live-broken bug — `ClaimTypes.Name` never populates against this app's Auth0 config — automated tests couldn't catch). Held without exception since: 6.1/6.2/6.3, 7.1, 7.2 each performed genuine live Auth0/Chrome session before reaching `done`.
- **Live-resize verification procedure (breakpoint/layout checks, e.g. 660px `wide:` breakpoint).** In Claude-in-Chrome sandbox, `resize_window` on already-navigated tab does **not** change real `window.innerWidth` (Stories 8.1/8.2/8.6/8.7), and some sessions clamp window to hard floor (8.3: exactly 660px, coinciding with this app's breakpoint). Follow this order — don't rediscover it:
  1. Close prior tabs, then `tabs_create_mcp` **fresh** tab (tabs in group share one window/viewport, so stale tab skews measurement).
  2. `resize_window` that new tab to target width **before its first `navigate`**, then navigate to app. Resizing after navigation, or re-navigating after second resize, has no effect.
  3. **Confirm width, don't assume:** read `window.innerWidth` via `javascript_tool` and require it equal target. Measure with `getBoundingClientRect()`/`getComputedStyle()` rather than eyeballing screenshot. **For checks needing real key presses (Tab order, focus, shortcuts):** take `screenshot` first — key presses only reach page after screenshot call has focused it, and plain `Tab` right after `navigate` registers no stops (Story 10.3). Then press keys and read `document.activeElement` after each.
  4. Cover both sides of each breakpoint with one tab per width (e.g. 500px, 659px, 660px, 1000px). If 659px request reads back 660px, that is clamp floor — it is **not** 659px check. Usual cause: stale tab still open in same window (clamps every tab's width to 659/660, whatever target): close all other tabs in window, create fresh tab, redo resize-then-navigate order. If still reads back 659/660, retry in fresh tab group or ask user. Readings of exactly 659 or 660 for *other* targets (e.g. 500 or 1000) mean same stale-tab clamp — don't record as passes.
  5. In-tab resize across breakpoint without reload (live `matchMedia` `change` swap) can't be driven by automation — **ask user to resize real window** and record what they observe. Don't skip.
  6. **Not acceptable substitutes** for live-check task: Playwright `setViewportSize()` spec (keep as regression guard, but doesn't satisfy gate), same-origin iframe (media-query `change` events don't fire; 8.12), or check that silently landed on different width. Substitute stays blocked in review unless user explicitly accepts it in review and acceptance recorded in story (8.12: Ralf accepted iframe evidence on 2026-09-30).
  Traces to Epic 8 retro (2026-10-02, Action #4): live-verification step substituted or partial in 6 of 12 stories (8.1, 8.2, 8.3, 8.6, 8.10, 8.12), each caught only in review.
- **Amend ACs at decision time.** When Ask First or review decision changes, adds or removes Acceptance Criterion, edit AC in story file in same session and mark it `AMENDED <date, decision>` (who decided, one clause on what changed). Keep old text visible as `~~struck through~~` right after new text; new AC gets `AMENDED <date, decision> (added)`. Header HTML comment or Dev Notes remark alone does not count, because ACs are what dev-story, review, Acceptance Auditor read. If change also revises another story's AC or an AD, mark that source too (one-line `AMENDED` note on old text pointing at new story). Create-story changes that only add implied requirements stay labelled "implied requirement", not `AMENDED`. Traces to Epic 10 retro (2026-10-10, Action #1): Ask First and review decisions had changed ACs without leaving trail in AC text.

**Anti-patterns to avoid (each traces to real architecture decision — see `_bmad-artifacts/planning/architecture/architecture-energy-tracker-2026-08-09/ARCHITECTURE-SPINE/invariants-rules.md`):**
- **Don't reimplement Bonus-Decay Normalization (AD-5):** pace/savings formula shared by Pattern Detective and Tariff Savings Radar lives in exactly one place, `Domain.Calculations.BonusDecayNormalizer` — never locally-adjusted copy in feature.
- **Don't hard-branch on AI availability (AD-8):** `IAiPlausibilityClient` resolves to no-op when unconfigured — features must not check "is AI enabled" and take different code path; correlation field simply absent from response.
- **Don't parse smart-plug files outside `ISmartPlugParser` (AD-9):** one port, one adapter per vendor (`EveHomeXlsxParser`, `MerossCsvParser`). Eve Home timestamps parsed as **local time, never UTC-converted** — deliberate, documented behavior, not bug to fix. Meross device identity comes from filename pattern, not file-body metadata.
- **Don't hard-delete or live-FK-join Room/PowerPoint/Device (AD-10):** soft-deleted (`ArchivedAt`). `SmartPlugReading`/`Event` snapshot Room/PowerPoint/Device identity **by value** at write time — live FK join would incorrectly rewrite history when Power Point's Room assignment changes later.
- **Don't build bespoke "keep the old value" column per entity (AD-11):** all correction audit trails go through single `AuditCorrection` table + `IAuditCorrectionRecorder`. Carve-out: FR-23's full-dataset restore is wholesale replace, not edit, doesn't go through this mechanism.
- **Don't allow two open regression prompts per Main Meter (AD-12):** at most one open `MeterRegressionPrompt` at a time, ordered by reading timestamp (not entry order).

**Edge cases agents should handle:**
- Open `MeterRegressionPrompt` excludes its triggering reading (and everything chronologically after it) from baseline computation until resolved.
- Job envelopes must be plain JSON-serializable records — delegate/closure payload works against `InProcessChannelJobQueue` but silently fails to serialize on `AzureStorageQueueJobQueue`.
- **Multi-field edits:** capture every "old" field value into local *before* calling repository's write/update method, not just first field touched. EF Core's identity map can return same tracked entity instance across `FindByIdAsync`-then-`UpdateAsync` call pair, so reading field's "old" value after write already reflects new value (silently records `OldValue == NewValue` in `AuditCorrection` row). Only real-`DbContext` test (not NSubstitute-mocked one) can catch this — found in Story 5.1's `EditTariff`.
- **"Lock field X unless condition Y" gates:** explicitly test whether gate can be bypassed by editing *different* field in same or sequential request, not just field lock is nominally about. Found in Story 5.1: pairing `ContractStartDate` change with price-field edit in one request let override gate evaluate against stale pre-edit date.

**Security:**
- Every route requires authentication except OIDC callback — don't add unauthenticated endpoint without explicit, reviewed reason.
- Never store auth token client-side (`localStorage`/`sessionStorage`/JS-readable cookie) — enforced by `FrontendDoesNotStoreAuthTokensTests`. Sole, allowlisted exception: per-device theme preference (`'light'`/`'dark'`, FR-35) in `web/src/lib/color-scheme.ts` (+ its test); `web/public/theme-init.js` (pre-paint copy, Story 11.7) isn't scanned (guard covers only `.ts`/`.tsx` under `web/src`), and `color-scheme.test.ts` runs it to keep in sync. Session state lives only in httpOnly cookie.
- Logout is `fetch` `POST /logout` (with CSRF header) that clears cookie and answers `200 { redirectUrl }`; SPA navigates to that URL. Form POST answered with 302 to identity provider would be blocked by CSP's `form-action 'self'`, so CSP not widened. OIDC sign-out event (`FederatedLogout.cs`) must keep protecting `State`, or provider's confirmation lands on blank page.
- Secrets (DB connection string, OIDC client secret, AI API key) come only from env vars/Container Apps secrets/`.env` — never committed, never baked into image.
- Never log, print or paste Data Protection key XML (`DataProtectionKeys.Xml`); check key rows with counts only. Outside Development or explicit opt-out no row may contain `<masterKey` (revoked pre-cutover rows excepted until deleted). Key Vault role: Key Vault Crypto Service Encryption User on key only, never vault (guarded by `DataProtectionKeyVaultInfraTests`).

**Performance/operational gotchas:**
- `/health` must stay liveness-only (no DB/dependency check) — adding one risks restart loop when Postgres/Azure SQL briefly slow, since Container Apps' probe would fail and cycle container.
- OTel logging (`Otel:Exporter=AzureMonitor`) deliberately does not forward logs to Application Insights in Azure — only traces + metrics — because Application Insights shares same Log Analytics workspace/quota that stdout logging already streams into; second log path would double-ingest against shared daily cap.
- Check `docs/local-vs-azure-deltas.md` before touching auth, ingress, database provider, or deploy pipeline — local dev/self-host and Azure structurally diverge (TLS termination, ACR/managed-identity credential timing, region provisioning, blank-env-var handling) in ways only surfacing on live Azure deployment.
