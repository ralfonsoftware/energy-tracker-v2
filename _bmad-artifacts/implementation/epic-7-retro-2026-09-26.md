## What Went Well

- **The hotfix-gate discipline held a third epic running, under real incident pressure this time, not just planning-time discipline.** The Epic 4 retro's hard gate ("no fix to already-shipped code merges without a linked spec/story doc, regardless of size or urgency") was tested against genuine production-incident pressure and held: `spec-household-export-oom-fix.md` was written with full frozen intent, boundaries, an I/O matrix, and a Spec Change Log before/as part of the fix.
- **Adversarial + edge-case review caught a real regression in the fix itself, in the first pass.** Both `bmad-review-adversarial-general` and `bmad-review-edge-case-hunter` independently converged on the same bug: the JSON writer flushed once per whole collection instead of per DB page, which would have re-buffered unbounded JSON for one large collection — reintroducing the exact OOM the fix existed to close. Fixed with a real `Pipe`-backpressure regression test, not just an HTTP-level assertion (the spec itself notes HTTP-level checks "can't reliably tell 'flushed periodically' from 'buffered then flushed once'").
- **Live verification against real household data found two real bugs neither automated suite could reach — third epic in a row this pattern holds.** 7.2's live restore against a household with genuine historical Smart Plug import data found two previously-undiscovered `DeleteBehavior.Restrict` FK conflicts (`BackgroundJob.QueuedByHouseholdMemberId`, `SmartPlugImportGap.PowerPointId`), invisible to every synthetic fixture because none had ever created that exact row shape. The same live pass also caught one Pass-1 review fix that never got applied to `MeterReading.KwhValue`'s range validation.
- **Both Epic 6 retro kickoff checks assigned to 7.2 were resolved by design, not just checked off**: the Stories 3.8–3.10 bulk-write/chunking lessons (`ChunkSize=200`, 120s timeout, one outer transaction) and the `DateTimeOffset` value-comparer gap (resolved structurally — restore never does the UPDATE-shape that gap requires).

## What Didn't Go Well / Patterns

1. **A correctly-disclosed, correctly-reasoned deferred risk still became a production incident within days.** 7.1's review named the exact failure mode and its trigger condition, but "revisit if real data volume risks the ceiling" had no monitoring hook behind it — the risk was discovered by an actual `OutOfMemoryException`, not by a signal that fired before the crash.
2. **That gap isn't fully closed even now.** The OOM fix's own deferred-work entries note the export's *success* path still has no duration/row-count/page-count telemetry — only the fault path logs. Nothing would surface the next household trending toward the same danger zone before it OOMs again. **Closed this retro — see Action Items.**
3. **The Wattage Plausibility AI backend decision (Epic 6 Action Item #2) aged two full epics without a decision.** Correctly non-gating throughout, but aging. **Escalated this retro — see Significant Discovery below.**
