- **Scope discipline held all epic long.** Every Epic 5 story's "Scope Reality Check" section explicitly fenced off later stories' territory (5.1 refused to touch 5.2/5.3/5.4's work, 5.2 refused 5.3's, etc.) — no scope bleed shows up anywhere in the review findings.
- **Both "first real consumer" risks flagged by the Epic 4 retro landed clean.** `AuditCorrection`/AD-4 held up for Tariff (needed one additive port method for multi-field edits, not a rewrite); `BonusDecayNormalizer`/AD-5 got its first real caller in 5.2, verified line-for-line against the mockup's own worked numbers before being trusted.
- **Server-computed verdict pattern reused deliberately.** 5.3's `IsBonusIncludedWorthSwitching`/`IsBonusNormalizedWorthSwitching` explicitly followed `GetCurrentStatus`'s established "compute the enum/verdict server-side, frontend only renders it" precedent instead of re-deriving from raw numbers in JSX.
- **Color-contrast discipline matured.** 5.3 and 5.4 both *actually computed* WCAG contrast ratios via a relative-luminance script (not eyeballed) before shipping new color tokens — a direct, deliberate response to `review-accessibility.md`'s earlier named failure on this exact class of token.
- **1.12's genuinely-ambiguous design point was flagged, not guessed.** The offline-queue cross-Household misattribution risk was called out explicitly in the story as unresolved by AD-17/AD-16, with a recommended default — and Ralf's review-time decision (household-tag every queue entry, refuse to flush a mismatched one) closed the actual mechanism, not just the disclosure.
- **Every Epic 4 retro process fix held.** Zero undocumented hotfixes this window; the live-Auth0/Chrome hard gate fired correctly on the one OIDC-touching story (1.12 — twice: once pre-review, once re-verified after a patch); the i18n/`Intl.*` and unmounted-guard checklist reminders show no recurrence in any Epic 5/1.12 review finding.

## What Didn't Go Well / Patterns

1. **5.1's identity-map bug is a new correctness trap worth naming.** `EditTariff` read "old" field values *after* calling the repository's update call — EF Core's identity map returned the same tracked entity instance, so audit-correction rows briefly recorded "old == new" until fixed. `EditMeterReading` already guarded against this for its one correctable field; `EditTariff` hadn't yet extended that discipline across Tariff's five. Only the real-`DbContext` API test caught it — the mocked Application-layer unit test couldn't.
2. **5.1's locked-field override had a real bypass**, found in review: pairing a `ContractStartDate` change with a price edit in the same (or a sequential) request let the server-side gate evaluate against the stale pre-edit date. A "lock field X unless condition Y" gate needs an explicit bypass-via-a-different-field check every time one is built.
3. **The WCAG-contrast-automation gap has now been deferred three retro cycles running** (Story 2.2b → 5.3 → 5.4), each time as "pre-existing, not this story's problem." Individually reasonable; three cycles in, it reads as unowned. Escalated this retro — see Action Items.

### Action item #4 — closure note

Landed as a Vitest unit test, not a lint step: `web/src/lib/contrast.ts` (WCAG relative-luminance/contrast-ratio math, `#hex`/`rgb()`/`oklch()` parsing, alpha compositing) plus `web/src/color-tokens.contrast.test.ts`, which reads `index.css` directly (not a copied snapshot of values) and asserts AA (4.5:1) for every pair a story has actually hand-verified so far — Status triad badges, both `--attractiveness-*` badge/figure/supporting-text pairs, `--tariff-check-card-*` — in both themes, composited over the real backdrop each token renders on (glass-card surface vs. bare page). All 32 assertions pass; the computed ratios reproduce the manually-verified figures from Stories 2.5/5.3/5.4 almost exactly (e.g. tariff-check-card light 4.53:1 vs. the claimed 4.52:1), confirming both that the prior manual math was right and that the automation gap is now closed. One real bug was caught building this: the first draft fed `--attractiveness-signal-supporting-text` (itself `rgba(..., 0.82/0.7)`, semi-transparent) straight into the contrast formula without compositing it over its background first, which silently overstated its ratio — fixed by compositing every text color over its resolved background before measuring luminance, which is now the unconditional path for every assertion in the file. Full frontend suite green (353/353, up from 321), `tsc -b`/`oxlint`/`vite build` all clean. Deferred-work entries for story-2-2b, 5-3, and 5-4 marked resolved.
