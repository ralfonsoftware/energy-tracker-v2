## What Went Well

- **Planning → UX → implementation → testing fit together** (Ralf). The 2026-09-23 critique mockup carried straight into ACs; the 09-28 live review became Stories 8.6–8.9 inside the same epic.
- **Shared infrastructure built once, reused throughout:** `--breakpoint-wide` / `wide:` variant (8.1), `QuietCard` (8.3), `data-slot="{page}-content"` wrappers, the `app-shell.spec.ts` Playwright pattern. Later stories were mostly assembly.
- **Three-reviewer pass kept raising test rigor:** non-diagnostic Playwright assertions in 8.3, 8.9, 8.10, 8.12 were replaced before they could give false confidence.
- **Live Auth0/Chrome verification again found what automation couldn't:** the missing `email` OIDC scope (8.1, then pinned by `OidcConfigurationTests`) and the System-segment label bug (8.10).
- **Deferred items were picked up by the next story** (8.2 Import label → 8.3; 8.10 strip `pending`/`nowrap` → 8.11/8.12).
- **"Scope Reality Check" in Dev Notes** resolved stale epic AC text (8.2, 8.3, 8.4, 8.5) explicitly rather than silently.

## What Didn't Go Well / Patterns

1. **Live-verification step substituted or partial in 6 of 12 stories** (8.1, 8.2, 8.3, 8.6, 8.10, 8.12): Playwright instead of a live resize, unreached branches, a 659px check landing on 660px, an iframe instead of a real tab. Caught in review each time. Root cause is environmental: `resize_window` doesn't change the real `innerWidth` in the sandbox tab.
2. **Locale and theme coverage repeatedly reported as English-only / one-theme** (8.3, 8.4, 8.10). With toggles now shipped (8.10, 8.11) these are user-reachable.
3. **Recurring deferred themes with no owner:** no keyboard tab-order tests (8.4; `wide:order-N` reordering in 8.5/8.8 is an untested WCAG 2.4.3 risk); the 660px breakpoint lives in `--breakpoint-wide`, `WIDE_QUERY` and e2e with no sync check (8.12), and `max-w-[900px]` is repeated across 4 pages; dual-render tests rely on DOM-order indexing (8.1, 8.5).
4. **`deferred-work.md` has become unmanageable:** 519 lines, ~165 bullets, ~58 sections, no status markers, mixed insertion order (newest sections at the top, most others appended at the end). Nothing ever leaves the file.
5. **Account section placement is inconsistent across breakpoints:** Profile menu top-right at ≥660px, last section in Settings on phone. Not a blocker; moving it first isn't right either. Needs UX design.
