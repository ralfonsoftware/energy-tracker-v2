## What Went Well

- **Adversarial review kept finding real bugs, not noise.** 1.10: all three review layers independently caught the same cascade bug (`roomHasVisibleChildren` didn't recurse into `powerPointHasVisibleChildren`, silently hiding a live Device under a doubly-archived Room/Power Point pair). 2.8: found an unguarded two-`SaveChangesAsync` write (value update + `AuditCorrection`) with no shared transaction — fixed by building this codebase's first `IUnitOfWork` port/adapter — plus an integer-overflow pagination bug and a spurious-409-on-no-op-edit bug.
- **3.4's "propose a recommended default, confirm with Ralf" pattern kept paying off**, twice surfacing empirical discoveries mid-implementation (e.g., EF Core's SqlServer provider auto-filtering nullable unique indexes, correcting the story's own premise that a gap was Postgres-only).
- **Post-UX-freeze scope decisions (2.7, 2.8) were confirmed in-document with Ralf each time**, both mirroring the prior story's placement pattern (Dashboard text-link trigger) rather than guessing.
- **Epic 2's action items landed and were used**: Auth0 test user unblocked real live-browser verification (used in 3.2 and 3.3); the `npx shadcn add` CLI bug never recurred in Epic 3's frontend work.

## What Didn't Go Well

- **Story 3.4 needed a second full adversarial review round before commit** — 13 findings round 1, 16 more round 2 (including a real bug: a cancelled per-row import fallback's partial row collided with itself on queue-redelivered retry). The most review-churn-heavy story of the window.
- **The review-diff tooling gap repeated twice in a row**: `git diff` silently excludes untracked files, and both 2.7's and 2.8's first-pass diffs were missing brand-new files until regenerated with `git add -N`. Same bug, same manual fix, two stories running.
- **Live-browser verification stayed inconsistent** even after Epic 2 unblocked it — 3.2/3.3 got it, 3.1/3.4 relied on automated suites alone. Nothing shipped broken, but the capability isn't being reached for uniformly.
- **Story 2.8's review surfaced that Epic 4's Story 4.3 ("Correcting a Meter Reading") is now stale** relative to what actually shipped — see Significant Discovery below.

## Significant Discovery: Epic 4 Definition Update Required

Story 2.8 built a standalone Meter Reading History page (list + inline edit, with `IUnitOfWork`-backed audit-trail writes and AD-4 optimistic concurrency), reachable via a Dashboard Status-card text link. Epic 4's Story 4.3 ("Correcting a Meter Reading") assumes editing happens via Trend History (Story 4.1, not yet built) and requires `IStatusRecomputeService` to recompute Status forward from the corrected reading through to present — neither of which 2.8 does.

**Ralf's decision:** consolidate rather than duplicate. Before Story 4.1 is drafted, Epic 4's definition needs updating so that:

1. **Story 4.1 (Trend History) absorbs Story 2.8's Meter Reading History functionality** — the browsable list becomes part of the Trend History surface, not a separate page.
2. **Story 4.3 keeps its ACs exactly as currently specified** — edit via the (now-merged) Trend History surface, 409 on concurrent edit (AD-4 — already built in 2.8, reusable), original-value preservation via `AuditCorrection` (AD-11 — already built in 2.8, reusable), and the net-new piece: `IStatusRecomputeService` recomputing forward from the corrected reading through to present, updating affected `StatusSnapshot` rows.
3. **The Dashboard Status card's standalone "History" text-link (built in 2.8) gets removed** once the merge lands, so there is a single place to browse and correct Meter Readings, not two.

This is a required epic-content update, not a story-level task — flagged as the top prep item before Epic 4 story-drafting begins.
