## What Went Well

- **Spike-before-build discipline (3.8 → 3.9)**: the bulk-write throughput spike measured real Postgres and real Azure SQL Basic tier before 3.9's design was finalized — caught the `[HouseholdId, IntervalStart]` match-key as a hard no-go and the ~85–135× SQL-Server-Basic-tier slowdown before either became a production surprise. Reinforced by the prior brainstorming/architecture session that shaped the approach up front. Team agreed: worth deliberately repeating for future expensive, hard-to-reverse calls, not just when a story happens to be a spike.
- **`spec-trend-chart-time-axis`**: tightly-scoped intent doc (no charting library, don't touch sibling components, height stays constant) shipped clean — 15/15 tests, zero lint drift. A model for how a disciplined spec boundary makes implementation straightforward.
- **The Smart Plug import arc (3.5–3.9 + PR #40/#41) matured into something solid**, not because it arrived that way, but because each story kept surfacing real things under load (StrictMode double-upload, duplicate-row cleanup, bulk-write verdict, watermark correction, Azure permission gap, transaction-rollback gap) and got hardened in response.
- Previous retro (Epic 3, 2026-08-23) follow-through: **all 6 action items done**, including the Epic 4 definition update being followed exactly as decided (4.1 absorbs 2.8, 4.3 stays narrow) — the retro's plan held under real execution, only needing a further AC #3 wording correction (buildable single-`RecomputeAsync`-call framing) resolved cleanly during 4.3's story creation.

## What Didn't Go Well / Patterns

1. **Undocumented hotfixes** (PR #40, #41) — both were real, production-surfaced integration gaps between independently-correct decisions (AD-21's least-privilege grants vs. Story 3.9's `EFCore.BulkExtensions` CREATE TABLE need; a status-commit-before-full-operation-completes race) but shipped with **zero spec or story trail**, unlike three sibling one-shots in the same window that did go through the `spec-*.md` process. Root cause (team consensus): timing pressure — under incident/urgency, writing the doc feels like overhead standing between the fix and relief, even though the machinery already exists and works fine when used.
2. **Live Auth0/Chrome verification kept getting deferred** across 3.5, 3.6, 4.1, 4.2 with no consistent follow-up mechanism. The one time it was checked (3.6, during code review, not dev-story), it found a real, live-broken bug (`ClaimTypes.Name` never populates against this app's Auth0 config) that automated tests had no way to catch. The deferral pattern was masking, not just delaying, real risk.
3. **Locale/i18n hardcoding recurred 3×** (3.6, 4.1, 4.2 — 4.2's own Dev Notes said "apply the same care as 4.1" and still shipped hardcoded). Always caught in review, never reached production.
4. **Missing unmounted-component/async-cleanup guards recurred 3×** (3.5's StrictMode double-upload, 3.6's `JobHistoryList`, 4.3's chart-staleness race). Always caught in review or testing, never reached production.
