## Story

As a self-hoster or operator,
I want the image and configuration to behave the way the docs say,
so that following `.env.example` works and the image matches what CI verified (audit S5, S7, C11, C1).

## Acceptance Criteria

1. **Given** the Dockerfile, **when** the image is built, **then** the runtime stage runs as `USER $APP_UID`, and the build stage copies `Directory.Build.props` and `global.json`, so the NuGet-audit gate and the SDK pin apply to the shipped image.
2. **Given** a missing `ConnectionStrings:Default`, **when** the app starts outside Development, **then** it fails with a clear error. The `change-me` fallback is used only in Development.
3. **Given** OIDC is not configured, **when** `/login` is requested, **then** the response is 503 with a clear "not configured" message, not a 500.
4. **Given** the AI configuration, **when** this story is done, **then** the code reads the `Ai:*` section (`Ai:Endpoint`, `Ai:ApiKey`, `Ai:Model`, `Ai:BackendLabel`) used by `appsettings.json`, `.env.example`, `docker-compose.yml` and Bicep. The stale Bicep "placeholder" comment is fixed, the selected adapter is logged at startup, and a test binds the documented keys. Epic 9's text references are updated (proposal §4.4).
5. **Implied (the image change must be provable, and not only true on the day: the AC is a property of a text file that the next edit can silently undo, and the repo's style is an executable guard):** `tests/EnergyTracker.Architecture.Tests/DockerImageMatchesTheVerifiedBuildTests.cs` (text scan with comments stripped, non-vacuous, style of `HouseholdImportIsStreamedTests`) fails when: the backend-build stage does not copy `global.json` and `Directory.Build.props` before its `dotnet restore`; the final `FROM` stage has no `USER $APP_UID` (or a numeric non-zero id, but never `root`/`0`) before `ENTRYPOINT`; a later `USER root` / `USER 0` appears after it; or the file no longer has three `FROM` stages / no `ENTRYPOINT`. Mutation-checked (Task 8). The audit's third S5 bullet (digest pinning, `HEALTHCHECK`) is **not** in the epic ACs and stays out (see "Considered and left out").
6. **Implied (a blank value is how Container Apps and `.env` express "not configured", docs/local-vs-azure-deltas.md D4; `??` does not catch it):** a `ConnectionStrings:Default` that is **empty or whitespace** counts as missing. Outside Development it fails exactly like an unset one; in Development it falls back like an unset one. The error names the key (`ConnectionStrings:Default`, and its env form `ConnectionStrings__Default`), says what to do in one sentence, and never contains the fallback string, a password, or any configured value. A Development host with nothing configured still starts (every API test host, `scripts/run-api.sh`-less `dotnet run`).
7. **Implied (the fail-fast changes what a non-Development host needs, so every host in the repo that runs outside Development must say where its database is):** `DataProtectionStartupTests` builds `Production` hosts with **no** connection string today: after this story its refuse-to-start test would fail on the wrong message (the connection-string check runs first, line 124 of `Program.cs`, the Data Protection check is at line 303) and its opt-out test would not start. Both set `ConnectionStrings:Default` to an unreachable database string (the `SecurityHeadersTests.UnreachableDatabase` pattern; no connection is opened because `/health` is liveness-only and the refuse test throws at build), so each test still proves what its name says. A grep over `tests`, `scripts`, `docker-compose*.yml`, `infra`, `.github/workflows` and `web/playwright.config.ts` for any other host started outside Development without the setting is recorded in Completion Notes (the 2026-10-22 create-story pass found none: Compose sets it in both variants, Bicep sets it from the `db-connection-string` secret, `run-api.sh`/`migrate.sh` export it, the EF tooling uses the migrations projects' design-time factories and never `Program`).
8. **Implied (the 503 must not break the rest of the pipeline around `/login`):** (a) `/login` keeps `RequireRateLimiting(RateLimitPolicies.Login)` on both branches, so an unconfigured instance cannot be hammered either; (b) the body is RFC 7807 `application/problem+json` (project rule: no ad hoc error shapes) with `status` 503, a stable `title` and a `detail` that says sign-in is not configured on this server and names `Oidc__Authority`, `Oidc__ClientId` and `Oidc__ClientSecret` plus `docs/self-hosting.md`; it contains no stack trace and no configured value; (c) the configured path is byte-for-byte unchanged (302 to the provider with the same `returnUrl` handling; `IsSafeLocalReturnUrl` untouched) and has a regression test; (d) `POST /logout` is untouched (it already tolerates an unconfigured OIDC); (e) `RateLimitingTests`' comment that `/login` "throws inside the host" is now false and is rewritten (its `catch (InvalidOperationException)` stays for the multipart routes, only the claim about `/login` goes).
9. **Implied (what "the code reads the `Ai:*` section" has to include so the audit's failure cannot recur):** (a) all four keys are read in **one** place, once, at the composition root, and the legacy `AiPlausibility:*` keys are no longer read anywhere (no fallback; Q2); (b) a blank `Ai:Endpoint` selects `NoOpAiPlausibilityClient` and `AiPlausibilityBackendOptions(Configured: false, …)` exactly as today, a non-blank one selects `OpenAiCompatibleClient` with that base address and, when `Ai:ApiKey` is non-blank, `Authorization: Bearer <key>`; `Ai:Model` blank means `"default"`, `Ai:BackendLabel` blank means `null` (all four values trimmed, as today); (c) a non-blank `Ai:Endpoint` that is not an absolute `http`/`https` URI **fails startup** with a message naming `Ai:Endpoint` (today `new Uri(...)` throws `UriFormatException` lazily when the typed client is first resolved, i.e. inside the first background job, where it is swallowed as a generic failure and the self-hoster is told nothing; Q1); (d) the startup log line states the selected adapter, `Ai:Endpoint` reduced to `scheme://host[:port]` (no userinfo, path or query), the model and the label, and **never** the API key; the unset case logs that no backend is configured and the Household toggle then has no effect; (e) the documented keys reach the code through **every** documented route: `appsettings.json` (all four keys present as `""`), `.env` → `docker-compose.yml` (`AI_ENDPOINT`, `AI_API_KEY`, `AI_MODEL`, `AI_BACKEND_LABEL` → `Ai__*`), `scripts/run-api.sh` (same mapping, it mirrors Compose), and Bicep (`Ai__Endpoint`, `Ai__ApiKey`, and the two new plain empty `Ai__Model`, `Ai__BackendLabel`).
10. **Implied (drift guard for AC #4, in this repo's style: prose rules die, executable ones do not):** `tests/EnergyTracker.Architecture.Tests/AiConfigurationKeysAreOneSetTests.cs` fails when the code, `appsettings.json`, `.env.example`, `docker-compose.yml`, `scripts/run-api.sh` and `infra/modules/container-app.bicep` do not agree on the key set `{Endpoint, ApiKey, Model, BackendLabel}` (an `Ai__X` or `Ai:X` outside the set, a missing one, or any `AiPlausibility:` configuration literal under `src/`), and each scanned file must still exist and still mention the section (non-vacuous). This is the guard the audit asked for ("a test that binds the documented keys") from the other side: the host-level tests in Task 1.4 prove the code binds them, this proves the docs and deploy files only name keys the code reads.
11. **Implied (docs that would otherwise go stale):** `.env.example` (the four `AI_*` lines, the "reserved for a later epic" comment replaced), `docs/self-hosting.md` (line 62 says `AI_API_KEY` is "reserved for a feature not yet built": it is built, and the section names all four keys, that blank means off, that `AI_ENDPOINT` is the server root because the client appends `v1/chat/completions`, with the LM Studio and OpenAI shapes as examples, and that from inside Compose the host's LM Studio is `http://host.docker.internal:1234`), `docs/local-development.md` (line 300: the API falls back to `change-me` only in Development; a container, which runs as Production, refuses to start without the string), the blockquote at line 77 (`docker compose up` runs the API as Production: add the connection-string sentence), `scripts/run-api.sh` (its stale fallback comment and the `Ai__*` exports), `docs/data-export-format.md` line 89 (still names the options type's `BaseUrl`, which never existed on it: say `Ai:Endpoint`, `Ai:Model`, `Ai:ApiKey`), `src/EnergyTracker.Application/AiPlausibilityBackendOptions.cs`, `NoOpAiPlausibilityClient.cs` and `OpenAiCompatibleClient.cs` header comments, the two test comments that say `AiPlausibility:BaseUrl` (`AiPlausibilityEndpointsTests`, `EventEndpointsTests`), `_bmad-artifacts/planning/epics/epic-9-wattage-plausibility-ai-backend-decision.md` (line 71; line 3 was already updated by the proposal), and `_bmad-artifacts/project-context.md` (Task 6).

### What this fixes and why it is safe to change

- **S5 (Medium, verified).** The runtime stage has no `USER`, so the app runs as root; and the backend-build stage copies `Directory.Packages.props` and `src/` only, so the image is built **without** `Directory.Build.props` (the NuGet-audit gate: `NuGetAuditMode=all`, `NU1902`-`NU1904` as errors) and **without** `global.json` (the SDK pin and, indirectly, the test runner setting). ### Technical details the dev must get right

- **`USER $APP_UID`:** Docker expands environment variables in `USER`; the aspnet base image sets `ENV APP_UID=1654` and creates the `app` user (verified 2026-10-22: `docker run --rm --entrypoint printenv mcr.microsoft.com/dotnet/aspnet:10.0 APP_UID` prints `1654`, `id app` is `uid=1654(app) gid=1654(app)`). Place it after the `COPY` so the published files stay root-owned. A numeric id also lets an orchestrator's `runAsNonRoot` check pass (a name would not). ACA does not need any change to run it.
- **What the process writes:** `Path.GetTempPath()` (`/tmp`: uploads), nothing under `/app`. Data Protection keys and everything else are in the database; logs go to stdout. The Azure Monitor exporter's optional offline storage and `DefaultAzureCredential` token cache use a temp/home directory; the `app` user has a home (`/home/app`). Part R's log check is how this is proven.
- **Copy the three root files together** before `COPY src/ ./src/`; MSBuild finds `Directory.Build.props` by walking up from `/src/src/EnergyTracker.Api`, so it must be at `/src` (the `WORKDIR`).
- **Connection-string check:** use `builder.Environment.IsDevelopment()`. Do not call `GetConnectionString` twice; assign the fallback only inside the Development branch. The message must be written for the operator who sees only `docker logs`: key, env form, one sentence, pointer to `docs/self-hosting.md`. The existing test hosts throw out of `CreateClient()`/`Services`; check the chain with a `MessagesOf` helper as `DataProtectionStartupTests` does (a host builder wraps the exception).
- **`Results.Problem(statusCode: 503, …)`** writes `application/problem+json` through the registered `AddProblemDetails()` writer; `detail` is plain text. Do not include `Request.Host` or configuration values.
- **Typed HttpClient name:** `AddHttpClient<IAiPlausibilityClient, OpenAiCompatibleClient>` registers a named client called `IAiPlausibilityClient`; that is how a test reads its `BaseAddress` and default headers without reflection. If the typed registration moves into the new class, the name stays as long as the service type does.
- **Endpoint log form:** build it as `$"{uri.Scheme}://{uri.Host}" + (uri.IsDefaultPort ? "" : $":{uri.Port}")`; `GetLeftPart(UriPartial.Authority)` includes userinfo, so do not use it.
