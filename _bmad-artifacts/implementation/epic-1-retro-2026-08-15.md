**Date:** 2026-08-15
**Participants:** Ralf (Project Lead), Amelia (Developer, facilitating), John (Product Manager), Winston (System Architect), Sally (UX Designer), Murat (Test Architect)
**Status:** First retrospective for this project — no prior epic retro to cross-reference.

## Epic Summary

- **Delivery:** 9/9 stories complete (100%), ran 2026-08-09 → 2026-08-14, with one late fix (`387919d`, CI-flake correction to soft-delete timestamp precision) landing 2026-08-15.
- **Scope:** FR-26/27/28 (Household & Access, an MVP "Must" tier) delivered in full, no cuts.
- **Production incidents:** 2, both on 2026-08-13, both root-caused and resolved within the epic:
  - `infra-deploy.yml` silently reset the live Container App to a placeholder image on an unrelated secret-rotation run (fixed in Story 1.6).
  - OIDC `redirect_uri` resolved to `http://` instead of `https://` behind Container Apps' TLS-terminating ingress, because `ForwardedHeadersOptions.KnownIPNetworks`/`KnownProxies` default to loopback-only and never matched the ingress peer (fixed in Story 1.7).
- **Deployment status confirmed live and stable:** Ralf manually verified the deployed Azure instance end-to-end — full room/power-point/device setup flow including rename and delete — works cleanly.

## What Went Well

- Deliberate avoidance of premature dependencies: no router until actually needed (1.5 deferred react-router, 1.8 used a regex path match, 1.9 used local view-state).
- A single reused use-case shape (one port per aggregate, one class per verb), established in 1.5 and reused through 1.9, kept 9 stories' review surface uniform and made real bugs easier to catch.
- Strong code review discipline throughout: 1.8 caught an open-redirect bypass and an unincremented concurrency token pre-merge; 1.9 alone had 13 findings including "done but tests incomplete" catches.
- A real "verified live vs. structurally only" honesty norm already existed in the story records (1.2 through 1.7), even before this retro made it a formal gate.
- Local dev environment + real OIDC integration (dedicated Auth0 client registration, confirmed correctly separated from production) turned out to be strong enough to close the previously-open AC #3 verification gap from Story 1.7.

## What Didn't Go Well

- Verification consistently stopped at "deploys cleanly" / "passes review" and never extended to "confirmed working against the real deployed environment" — this gap produced both production incidents, neither of which was visible to CI or local review (the local dev process runs with no reverse proxy in front, so the `ForwardedHeadersOptions` codepath specifically never gets exercised outside of Container Apps' real ingress).
- Two pieces of already-completed work existed but were never integrated, rather than being missing outright:
  - An OpenTelemetry / observability baseline was never built — AD-19 only specified basic stdout logging → Log Analytics, with retention deliberately capped at 30 days for personal-household scale. No alerting, no APM/tracing, no dashboards exist.
  - A full UX design spec (`DESIGN.md`, dated 2026-08-08 — a day before implementation started) defines a deliberate dark-mode-first "liquid glass," green-eco visual identity with real design tokens and working mockups reaching as far as Epic 4/5. None of it made it into the app — `web/src/index.css` is unmodified stock `shadcn init` output.

**Key insight:** in three separate places this epic, good work existed — a testing discipline, a design spec, basic logging — but wasn't made a required, checked step. It stayed a norm people could skip under time pressure rather than a gate.
