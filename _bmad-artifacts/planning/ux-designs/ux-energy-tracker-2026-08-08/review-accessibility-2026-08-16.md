# Accessibility Review — New Mocks (2026-08-16 session)

## Overall verdict
The already-verified tokens (status triad, brand-accent teal, dark-mode primary button, tariff-quiet text) all hold up fine and were correctly reused. However, most of the genuinely *new* tokens this session — the nav-chrome inactive-tab color, Settings' tree/label quiet-text tier, onboarding/invite helper notes, the light-mode primary-button assumption, and the Frame 3 "map-divider" label in the Smart Plug Import mock — undershoot 4.5:1, typically because a low-alpha value tuned against an opaque near-black sheet/modal was reused against a much lighter translucent glass-card or lighter overall ground without re-checking. Separately, several icon-only or unpadded controls (device row Move/Rename/Delete at 24×24px, "Copy", back-crumb links, pill choices) fall well short of a comfortable tap target, and every sheet/modal overlay in the set places the dimmed background content before the overlay in DOM order with no visible `inert`/`aria-hidden` treatment — worth flagging for whoever wires these up.

## Findings

- **high** Bottom nav-chrome inactive tab labels/icons are close to invisible: dark `rgba(234,245,238,0.42)` on the screen ground (~#0C1611–#12201A) is only ≈3.8–3.9:1; light `rgba(30,42,28,0.5)` on the screen ground (~#EAF0DF) is only ≈2.96:1. Both are new tokens ("not yet rendered elsewhere" per this file's own comment) and both apply to persistent chrome on every screen. (`key-dashboard.html`, `.theme.dark .nav-item` / `.theme.light .nav-item`, line ~176 & ~209). *Fix:* raise to `rgba(234,245,238,0.56–0.58)` dark (≈5.8:1) and `rgba(30,42,28,0.65–0.68)` light (≈4.9:1) — matching the file's own `.date` quiet-text token (0.55) rather than inventing a new lower value.

- **critical** Device-row action buttons (Move/Rename/Delete) render at exactly 24×24px with only 2px gap between adjacent icons, for a destructive ("Delete") action among them. Far under the ~44×44 usable target, and the tight 2px spacing multiplies mis-tap risk between Rename and Delete. Repeats 3× per device row, 3 devices, both themes. (`key-settings.html`, `.icon-btn { width:24px; height:24px; }`, line 124, used at lines 254–271 and 331–348). *Fix:* bump to at least 40×40px (ideally 44×44) with ≥8px gap, or keep the icon glyph small but pad the button's hit area via `padding` so the tap target grows without changing the visual chip size.

- **high** Same icon-only buttons also rely solely on a `title` attribute for their accessible name, with no visible text (`title="Move to…"` / `"Rename"` / `"Delete"`). `title` isn't reliably exposed on touch/mobile and gives no visible on-screen label. (`key-settings.html`, `.icon-btn` markup, e.g. line 254–256). *Fix:* add `aria-label` matching the `title`, and/or a visually-hidden text node, so the accessible name doesn't depend on hover-only tooltip behavior.

- **high** Settings' quiet tree metadata — the chevron glyph and the "N power points / N devices" count — uses `rgba(234,245,238,0.4)` dark / `rgba(30,42,28,0.42)` light against the translucent `.tree-card`/`.card` glass surface (not the plain screen ground). Estimated ≈3.4:1 dark, ≈2.5:1 light — the light case is barely legible. (`key-settings.html`, `.chevron` / `.count`, lines 110–112, 185–186). *Fix:* raise to ≈`rgba(234,245,238,0.6)` dark and ≈`rgba(30,42,28,0.68)` light to clear 4.5:1 against this card surface — the existing `.device-row`/`.pp-row` text (0.72–0.88 alpha) already proves this surface needs materially higher opacity than the plain screen ground does.

- **high** `.field-label` ("Yearly Baseline (kWh)") and `.unit` ("kWh") in Settings use `rgba(...,0.45)` / `rgba(...,0.5)` against the `.card` glass surface, landing at ≈3.56:1 (dark) and ≈3.07:1 (light) for field-label, ≈4.06:1 (dark, borderline) for `.unit`. The identical class/color passes fine elsewhere in this file set only because those instances sit on darker or near-opaque surfaces (plain screen ground in `key-onboarding.html`, 92%-opaque `.sheet` in `key-log-reading-flow.html`/`key-household-invite.html`) — it's specifically the lighter `.card` fill (alpha 0.07) that breaks it here. (`key-settings.html`, `.field-label` / `.unit`, lines 143–145, 176–178). *Fix:* raise to ≈`rgba(234,245,238,0.6)` dark / ≈`rgba(30,42,28,0.62)` light for text used inside `.card`, distinct from the token used on darker surfaces.

- **high** Frame 3's new "or map to an existing one" divider label is `rgba(234,245,238,0.35)` at 10px against the modal-card surface — estimated ≈2.96:1, a hard fail, and this file's own inline comments show the designer already fixed two near-identical issues elsewhere in the same file to 0.55 ("was 0.34 = ~2.9:1, fails AA; corrected to text-quiet-dark") but missed this one, added in the same session. (`key-smart-plug-import.html`, `.map-divider`, line 260). *Fix:* apply the same correction already used twice in this file: `rgba(234,245,238,0.55)`.

- **high** The Frame 3 primary CTA button "Create Power Point…" and Onboarding/Settings' light-mode `.primary-btn`/`.save-btn` gradient (`#2E9B7E → #1E7A61`, white text, an explicitly-flagged `[ASSUMPTION]` new token) drops to ≈3.44:1 at the lighter end of the gradient and ≈4.22:1 at the gradient midpoint — under 4.5:1 for text that doesn't meet the "large text" bold-size exemption (14px bold requires ~18.7px to qualify). (`key-dashboard.html`, `.theme.light .primary-btn`, line 207; reused by `key-settings.html` `.theme.light .save-btn`, line 179). *Fix:* darken the gradient stops (e.g. `#227A61 → #145A47`) or keep white text but raise the darker stop's weight so the lightest point of the gradient still clears 4.5:1 against white.

- **high** Onboarding's "I'll set this later" skip link combines a contrast fail with a near-zero tap target: `rgba(234,245,238,0.4)` (≈3.5:1 on the plain screen ground) and no padding at all — the clickable area is only the ~14px text line-height, well under any usable target, for a real, functional skip action. (`key-onboarding.html`, `.skip-link`, line 96). *Fix:* raise color to `rgba(234,245,238,0.6)`+ and add `padding: 10px 12px` (or equivalent) so the hit area reaches ~40px+ tall.

- **medium** Onboarding's clarifying helper notes ("An explicit choice — never silently defaulted", "Picked a preset above, or type your own…") use `rgba(234,245,238,0.4)` on the plain screen ground, ≈3.5:1. (`key-onboarding.html`, `.helper-note`, line 80). *Fix:* raise to `rgba(234,245,238,0.55)` to match the already-established `.step-body` quiet-text tier in the same file.

- **medium** Household invite's "equal access" framing note — the one line of copy carrying the "no admin/owner role" trust message — is `rgba(234,245,238,0.42)` against the ~92%-opaque `.sheet`, ≈3.74:1. (`key-household-invite.html`, `.equal-note`, line 87). *Fix:* raise to `rgba(234,245,238,0.58)`.

- **medium** Member list status text ("Joined 2 Aug 2026" / "Invited — hasn't joined yet") is `rgba(234,245,238,0.42)` against the `.member-row` tinted background, ≈3.62:1 — this is the only place a viewer can see whether an invite is still pending. (`key-household-invite.html`, `.member-role`, line 97). *Fix:* raise to `rgba(234,245,238,0.6)`.

- **medium** Settings-row/tree "→" arrow glyphs are lower-opacity than their sibling label text — `rgba(234,245,238,0.3)` dark / `rgba(30,42,28,0.32)` light in `key-settings.html` (est. ≈2.5:1 dark, ≈2.1:1 light), and `rgba(234,245,238,0.3)` in `key-smart-plug-import.html`'s pre-existing `.settings-row .arrow` (out of scope) is echoed by the same low value on Frame-3-adjacent rows. Low severity individually since the arrow is redundant with the row's visible label, but it's presented as real (non-`aria-hidden`) text content. (`key-settings.html`, `.settings-row .arrow` / `.arrow`, lines 149, 182). *Fix:* raise to at least `rgba(...,0.5)`, or mark the glyph `aria-hidden="true"` if it's meant to be purely decorative.

- **medium** Icon-only "Copy" action for the invite link has no padding of its own — only the shared `.link-row` container padding applies to the row, not to the button — leaving a hit area of roughly its text bounding box (~20×34px). It's the only way to copy the invite link. (`key-household-invite.html`, `.copy-btn`, line 81, markup line 133). *Fix:* give `.copy-btn` its own `padding: 8px 10px` and a `border-radius` so it has an independent, larger hit area.

- **medium** Several new/repeated pill and row controls render under ~38px tall against the ~44px guideline: `.choice-pill` (Language/Currency, ~35.6px, `key-onboarding.html` line 77), `.preset-pill` (~28px, reused in `key-settings.html` line 92 and `key-onboarding.html` line 83), the Date/Time `.field-input` pair in the Log Reading sheet (~36px, `key-log-reading-flow.html` line 102), `.map-choose-btn` (~37.6px, `key-smart-plug-import.html` line 259) and `.map-existing-row` (~35px, line 262), and `.save-btn` in the Settings Yearly Baseline card (~33px, `key-settings.html` line 97). *Fix:* add ~4–6px more vertical padding to each (e.g. `.icon-btn`-adjacent rows to 12–14px, pills to 10–11px) to clear ~40–44px.

- **medium** Back-navigation "crumb" links have no padding and rely on 12px text alone for their tap target (~14px tall hit area): `key-settings.html` (`.crumb`, line 79, "← Dashboard"), `key-household-invite.html` (`.crumb`, line 55, "← Settings"), `key-smart-plug-import.html` Frame 3 (`.crumb`, line 106, "← Settings"). *Fix:* wrap in `padding: 10px 4px` (or similar) so the link's hit area reaches a usable height without changing its visual size.

- **medium** Every sheet/modal overlay in this batch places the dimmed background content (`.backdrop`) before the sheet/modal in DOM order, with no `inert`/`aria-hidden` marked on the backdrop in the markup. As static reference these are inert by construction, but taken literally into implementation a keyboard/AT user would tab or swipe through the (visually suppressed) Dashboard/Settings content before reaching the actual sheet or modal. Affects: the Log Reading sheet and Meter Regression modal (`key-log-reading-flow.html`, `.backdrop` then `.sheet`/`.modal-card`, lines 149–184 and 194–220), the Invite sheet (`key-household-invite.html`, lines 118–143), and Frame 3's mapping modal (`key-smart-plug-import.html`, `.backdrop-dim` then `.modal-card`, lines 392–423). *Fix:* note in dev handoff that the backdrop container needs `inert` (or `aria-hidden="true"` + a JS focus trap) whenever the sheet/modal is open, and that focus should move to the sheet/modal on open.

- **low** The regression-classification modal's choice descriptions ("New meter installed, or a manual reset…" / "Old meter hit its max digit count…") sit right at the edge: `rgba(234,245,238,0.5)` against `.choice-btn`'s tinted background is ≈4.38:1, just under 4.5:1. (`key-log-reading-flow.html`, `.choice-sub`, line 128). *Fix:* nudge to `rgba(234,245,238,0.55)` to clear the line with margin.

- **low** The "or invite by email" divider label is `rgba(234,245,238,0.35)` against the ~92%-opaque sheet, estimated ≈3.0–3.1:1 — a decorative section divider, but rendered as real text. (`key-household-invite.html`, `.divider-row span.or`, line 85). *Fix:* raise to `rgba(234,245,238,0.5)`+, consistent with the fixes above.
